# Бронирование переговорной

- Демо: https://maddev-test.vercel.app/
- Репозиторий: https://github.com/ponkk513/maddev-test

React 18, TypeScript, Vite, TanStack Query, React Hook Form + zod, MSW, Vitest + Testing Library, ESLint + Prettier. Структура — Feature-Sliced Design.

## Запуск

Node.js 18+.

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # тесты
npm run check   # типы + ESLint + Prettier + тесты
npm run build   # production-сборка
```

Mock API (MSW) работает и в production-сборке, бэкенд не нужен. Подключить реальный API с тем же контрактом: `VITE_USE_MOCKS=false VITE_API_URL=https://api.example.com npm run build`.

## Что сделано

- Выбор даты (дата хранится в URL), таймлайн дня и список броней, создание, редактирование и удаление.
- Все бизнес-правила из ТЗ — чистые функции в [`entities/booking/model/rules.ts`](src/entities/booking/model/rules.ts). Их используют и форма (через zod), и mock-сервер.
- Касание границ (10:00–11:00 и 11:00–12:00) не считается конфликтом. При редактировании бронь не конфликтует сама с собой.
- Прошедшее время сегодня недоступно, на прошедшие даты форма не показывается.
- **409:** понятное сообщение о том, какая бронь мешает, список броней обновляется, введённые данные сохраняются. Отдельно обработаны 404, 422, 500 и обрыв сети.
- Состояния UI: загрузка, пустой список, ошибка с повтором, отправка формы.
- API отделён от UI интерфейсом `BookingsApi`, ответы сервера проверяются zod-схемами.
- Адаптивная вёрстка (одна колонка на мобильных). Доступность: подписи полей, `aria-invalid`, управление фокусом, `<dialog>`, live-регион для уведомлений, eslint-plugin-jsx-a11y.
- Тесты: правила, mock API, UI-сценарии (в том числе 409 с сохранением ввода).

**Как проверить 409 и ошибки сервера:** внизу страницы раскройте «Инструменты демо»:

- «кто-то успевает занять это время» — следующее сохранение вернёт 409;
- «Сервер недоступен» — все запросы отвечают 500;
- можно увеличить задержку сети.

Ещё один способ получить 409: откройте две вкладки и займите одно и то же время.

Допущения:

- начавшуюся бронь нельзя изменить или удалить;
- при редактировании меняются только время и название, дата — нет.

## Что не сделано

- Часовые пояса: всё время считается в часовом поясе браузера.
- Перенос брони на другую дату, повторяющиеся брони, несколько комнат, авторизация.
- E2E-тесты в браузере (Playwright) и автоматическая проверка доступности (axe).
